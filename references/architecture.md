# 视觉栈四层架构

## 目标

把“事实、叙事、共享视觉能力、渠道视觉决策”拆成四个可独立验收的层。每个字段只有一个主人，下游可以消费，不能偷偷重判或复制真源。

## 第一层：EP Research

唯一主人：`hekouwang-ep-research-skill`。

负责：

- 事实、证据、来源与访问日期；
- 数据口径、统计时点、样本范围；
- 判断状态、限定词、反方证据与不确定性；
- 授权、隐私和高风险表达边界；
- 下游不得改写的锁定事实 ID。

不负责最终标题、文章结构、渠道文案、主题和构图。研究包可以说明某组数据适合被解释，但不指定图表样式或页面布局。

## 第二层：Content Master

唯一主人：`hekouwang-content-master-skill`。

负责：

- 把锁定事实组织为文章叙事；
- 第一人称、标题、正文和发布文案；
- 来源与合规边界在成稿中的表达；
- 文章母本与文章母版网页；
- 向渠道输出 `content-contract.json`。

Content Master 可以决定文章网页的视觉叙事与主题表达，但不能拥有小红书 1080×1440 的构图实现。内容合同只回答“这一页说什么、依据什么、什么不能改”。

## 第三层：Visual Core

唯一主人：`hekouwang-visual-core`。

负责：

- 规范主题 ID 与历史别名；
- 跨渠道共享的设计 Token 与字体合同；
- 可复用基础组件和通道基础适配；
- `fit.js`、`shoot.js` 等确定性运行时；
- 安装、版本、兼容性和资源完整性。

Core 不包含 `SKILL.md`，不会被内容任务直接唤醒。它不拥有 EP 文案、页面角色、领域原生对象、文章网页叙事或渠道构图。

## 第四层：Channel Design

小红书主人：`hekouwang-xhs-theme-skill`；公众号与头条由各自 Design Skill 负责。

负责：

- 消费锁定的内容合同；
- 选择渠道主题和页面构图；
- 输出 `visual-plan.json`；
- 使用 Core 资源完成通道装配；
- 目标尺寸 fit、截图、平台兼容与人工视觉 QA。

渠道层可以压缩表达和重排顺序，但必须遵守内容合同的变更边界。缺内容字段时退回 Content Master，不代写事实、来源或发布文案。

## 两份合同

### `content-contract.json`

主人：Content Master。

建议字段：EP、渠道、研究包引用、文章母本引用、锁定事实 ID、来源引用、合规备注、变更策略，以及每页的角色、核心句、证据引用和不可改写边界。

不得包含：主题 ID、字体、组件、卡片位置、构图、fit 策略和视觉资产摆放。

### `visual-plan.json`

主人：对应 Channel Design Skill。

建议字段：内容合同引用、主题 ID、页面到内容页的映射、构图意图、领域对象、信息关系、视觉新增信息、素材引用与 fit 策略。

不得新增事实、改写数据口径、删除来源或改变证据等级。

## 资源进入 Core 的判据

同时满足以下条件才进入 Core：

1. 被至少两个通道稳定复用，或属于明确的跨通道基础设施；
2. 不携带某期 EP 的事实和文案；
3. 不替渠道决定具体构图；
4. 有稳定 API、测试和兼容策略；
5. 许可允许在目标仓库中分发。

不满足时留在 Content Master、Channel Design 或当期 `_build.py`。
